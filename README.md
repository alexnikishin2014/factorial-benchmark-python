# Factorial Benchmark: Python Performance Deep Dive

Мини-проект для проверки гипотез о производительности циклов в Python на примере вычисления факториала.

> ⚠️ На N=990 срез списка (`lst[1:]`) медленнее эталона в **35 раз** из‑за O(N²). Итераторный подход (`iter`/`next`) сохраняет скорость классических циклов, а анализ памяти показывает, где скрываются лишние аллокации.

## Зачем это нужно?

Цель проекта — не просто «написать 4 функции», а на реальных цифрах показать, как синтаксически лаконичные конструкции (вроде срезов) могут скрывать за собой квадратичную сложность. Также проверяю альтернативу — подход с явным итератором, который концептуально аналогичен сдвигу указателя.

## Ключевые выводы

1. **Антипаттерн со срезом убивает производительность.** Конструкция `rest = lst[1:]` внутри цикла копирует весь список на каждой итерации. Это превращает линейный алгоритм O(N) в квадратичный O(N²). В бенчмарке это видно чётко: подход со срезом медленнее эталона в 35 раз.
2. **Итератор — это не «медленно», это честно.** Вариант `iter_factorial_simple` показывает ту же скорость, что и классические циклы `for`/`while`. Это доказывает, что идея «двигаться по данным, не копируя их» технически эффективна.
3. **Память зависит от входных данных.** Высокий расход памяти в первом тесте итератора был вызван не механизмом итерации, а строкой `nums = list(range(...))`, которая материализовала весь список в памяти. При использовании ленивого `range` потребление памяти падает до минимальных значений.

Это отличный пример того, как одна лишняя строка кода может полностью исказить картину бенчмарка.
